## Причина зависания

`User::WaitForRequest` сначала ждёт сигнал request semaphore и затем проверяет
status. Готовое значение status само по себе не делает повторный wait безопасным.
Pair-wait уже расходует один сигнал. Старый код дополнительно ждал poll-таймер,
даже когда именно его завершение уже было обработано. Это могло поглотить
сигнал I/O deadline, затем общего deadline, а очистка оставалась ждать событие,
которое больше не придёт. Правило видно в [исходнике Symbian euser](https://github.com/SymbianSource/oss.FCL.sf.os.kernelhwsrv/blob/master/kernel/eka/euser/us_exec.cpp#L1150).

В прежней хостовой модели ожидание проверяло только status и не моделировало
расход сигналов. Это скрывало ошибку. Новая модель воспроизводит do/while,
счётчик семафора и восстановление чужих завершений. До исправления TCP-тест
дал 120000 мс вместо ожидаемых 30000 мс; после исправления проходит.

## Что исправлено

- После pair-wait второй сигнал дренируется только если socket status уже готов.
  Если сработал только poll, повторного wait poll-таймера нет.
- Немедленно завершившийся до входа в Wait запрос дренируется один раз.
- Backoff ожидает только poll, оставляя завершение delay для единственной очистки.
- В DoCancel приложения осталось только уведомление worker. Framework сам
  выполняет wait после DoCancel — см. [CActive::Cancel](https://github.com/SymbianSource/oss.FCL.sf.os.kernelhwsrv/blob/master/kernel/eka/euser/cbase/ub_act.cpp#L70).

Добавлены проверки баланса сигналов после каждого сценария, одновременного
завершения таймеров, мгновенного ответа, отмены и очистки. Тест компилирует
реальный library/src/n70wait.cpp. Отдельный тест компилирует настоящий DoCancel приложения
с моделью framework-owned wait. Это проверки модели API, не эмуляция прошивки.

## Что повторить на телефоне

Установить dist/N70Test.sis 0.9.1. Главный экран и заголовки новых журналов
должны показывать 0.9.1. Повторить Test client 0.9, Test TCP timeout и отмену
с последующим выходом/повторным запуском приложения. Для client ожидается
14/14; для TCP — 2/2, либо INCONCLUSIVE, если оператор сразу отклоняет адреса.

не были нормальным выполнением теста и не засчитываются как завершение.
