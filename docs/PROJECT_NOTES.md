# N70 HTTPS / TLS 1.2

Статическая библиотека для Nokia N70, Symbian OS 8.1a / S60 2nd FP3.
Qt и промежуточный сервер не нужны. Сборка: THUMB UREL, GCC из SDK.

## 0.9.1 проверена на настоящем N70

Новые журналы пользователя подтвердили 43/43 проверки в шести наборах:
client 14/14, TCP timeout 2/2, HTTP 13/13, API/gzip 12/12, отмена 1/1,
отдельный timeout 1/1. Прежние зависания GET 503 и TCP timeout устранены
в этих сценариях. TCP-ожидания завершились за 2140 и 2031 мс.
Серия сайтов — 9/10; letsencrypt.org по-прежнему завершился EOF.
[Полный отчёт и границы проверки](N70_RESULTS_0.9.1.md).

## Исправление 0.9.1: зависания таймаута и повторов

Журналы 0.9.0 с N70 подтверждают HTTP 13/13, API/gzip 12/12, отмену 1/1,
PUT/PATCH/DELETE, reuse и DisconnectL. Client-тест останавливался на первом
GET 503 с повторами, TCP-тест — на адресе 192.0.2.1. Исправлен учёт сигналов
request semaphore: повторный wait уже обработанного таймера мог поглотить
чужое завершение и заблокировать очистку. Исправлены сетевой poll и backoff;
убран лишний wait из DoCancel приложения — его выполняет CActive::Cancel.

Хостовая модель теперь учитывает сигналы семафора, do/while и восстановление
чужих сигналов. Старый код воспроизводит сбой, исправленный проходит тесты.
Оба проблемных набора нового SIS **0.9.1** повторены на телефоне и завершились
успешно. Разбор прежнего сбоя: [N70_RESULTS_0.9.0.md](N70_RESULTS_0.9.0.md).

## Новое в 0.9: методы, восстановление, keep-alive и повторы

- PUT/PATCH/DELETE с телом и Content-Type, наряду с GET/HEAD/POST.
- Проверка RConnection, ограниченное восстановление после сбоя и перебор
  нескольких IPv4 из DNS без повторного подключения к дубликатам.
- Одно сохраняемое TCP/TLS-соединение на клиент; проверяются origin, содержимое
  roots, idle timeout и полнота HTTP/gzip. `DisconnectL` освобождает свои handles.
- Повторы GET/HEAD с backoff, jitter и Retry-After; PUT/DELETE — по отдельной
  опции, POST/PATCH не повторяются. После выдачи заголовков sink повтора нет.
- SIS **0.9.0**: **Test client 0.9**, 14 проверок в client-tests.txt. Новые
  функции собраны, но ещё требуют запуска на телефоне. [Инструкция](PHONE_TESTS.md).
- ПК: `tools/test-http09.ps1 -Live`, ASan и 15 сетевых запросов; пять из них
  прошли по одному TCP/TLS-соединению. Симуляции не заменяют испытания радио N70.

## Новое в 0.8: Bearer, gzip, таймаут TCP

- `SetHeaderL`, `SetBearerTokenL`, `ClearHeadersL`: копируемые заголовки;
  защита от CRLF и подмены framing; удаление пользовательских полей при
  редиректе на другой сервер/порт.
- Потоковый gzip через zlib 1.4, включая gzip поверх chunked, CRC/ISIZE и
  отдельные лимиты сжатых/распакованных данных. zlib включён в статическую .lib.
- Общий и I/O deadline через RTimer. При таймауте TCP выполняются CancelConnect
  и Close до завершения исходного запроса; убрано ожидание только после CancelAll.
- SIS **0.8.0**: **Test API + gzip** → api-tests.txt, **Test TCP timeout** →
  tcp-timeout.txt. Подробно: [PHONE_TESTS.md](PHONE_TESTS.md), [HTTP_API.md](HTTP_API.md).
- Хостовые проверки: `powershell -ExecutionPolicy Bypass -File tools/test-http08.ps1 -Live`.
  Модели ожидания не заменяют повторную проверку TCP на телефоне.

серию на телефоне ещё нужно проверить. Обновление сохраняет состояние RNG.

## Установка и тесты

1. Установить новый `N70Test.sis` поверх старого. Ручная настройка генератора не требуется. Настроить правильные дату,
   время и Internet-точку доступа оператора (не WAP-прокси).
2. **Options → Test HTTPS** получает страницу `https://example.com/`.
   Результат — `C:\system\apps\N70Test\response.txt`.
3. **Options → Test 10 sites** проверяет Google, Cloudflare, Wikipedia,
   Python, GitHub, Microsoft, Apple, Mozilla, W3C и Let's Encrypt. Точные имена
   находятся в `library/include/n70testsites.h`. Для каждого создаётся отдельное
   TLS-соединение, DNS и TCP используют одну выбранную точку доступа.
   Результат — `C:\system\apps\N70Test\tls-tests.txt`.
4. Повторить оба теста без копирования каких-либо файлов, затем закрыть
   приложение, открыть заново и повторить. Сохранённое состояние должно
   продолжать обновляться после каждой попытки, включая неудачные запросы.

Ручной `entropy.bin` больше не нужен. В логе серии у каждого сайта указаны
PASS/FAIL, Symbian/BearSSL/I/O ошибки, стадия, версия TLS и первая строка
HTTP-ответа. `TLS=0x0303` означает TLS 1.2; версии 1.0/1.1/1.3 не разрешены.
PASS требует проверенного TLS 1.2 и получения HTTP-заголовков. HTTP 301/302/403
не являются ошибками TLS. Перенаправления не следуются автоматически.
Журнал записывается и сбрасывается на диск после каждого сайта.

На Windows 2026-11-15 все 10 сайтов прошли проверку BearSSL: 10/10,
TLS=0x0303, BearSSL=0. Wikipedia и Microsoft вернули HTTP 403.
Это не заменяет проверку серии на N70: сеть, CDN и сертификаты могут отличаться.

## Автоматическая инициализация (0.6)

Общий SIS не содержит начального секрета. По явному пожеланию пользователя
включён полностью автоматический **экспериментальный** режим без клавиш.
Его криптографическая стойкость не подтверждена. Он не равноценен проверенному
системному CSPRNG: хеширование не создаёт отсутствующую энтропию.

`GetAutoL` при первом запросе собирает 64 набора Math::Random(), FastCounter,
TickCount, даты и микросекунд времени, а также временные измерения после коротких
пауз планировщика. SHA-256 с отдельным доменным префиксом формирует начальное
32-байтное состояние. Количество байтов и наблюдений не является оценкой энтропии.
Math::Random здесь не объявляется криптографически стойким. Если начальный ввод
предсказуем, HMAC-DRBG не исправляет эту слабость.

Далее генератор HMAC-DRBG/SHA-256 обновляет файл состояния до начала каждого
соединения. Нет общего bootstrap.bin, фиксированного секретного ключа или
персонального установщика. Состояние сохраняется между запусками и обновлениями.
Существующее валидное состояние сохраняется, включая состояние от ручного
режима 0.5; файл от старого персонального варианта 0.4 не используется.
Повреждённое состояние не сбрасывается автоматически, ошибки сохранения
останавливают запрос. Начальная подготовка происходит в рабочем потоке.

Файл `C:\system\apps\N70Test\rng-device-v1.bin`: 8 байт версии, 32 байта
состояния, 32 байта SHA-256 checksum. Запись — временный файл, Flush, замена
основного файла; lock сериализует обращения. Checksum защищает от случайных
повреждений, не от подмены. S60 2nd не изолирует файлы от других нативных
приложений. Копирование состояния, откат резервной копии и потеря питания
остаются ограничениями. Новый автоматический режим ещё не проверен на N70.

Низкоуровневый GetL и методы с явно подготовленным состоянием сохранены для
приложений, которым нужен собственный проверенный источник. Ручной timing-метод
остаётся в API для совместимости, но тестовое приложение его больше не вызывает.

## Встраивание библиотеки

Добавить `include` из SDK ZIP в USERINCLUDE и SYSTEMINCLUDE MMP. Скопировать
`lib/n70https.lib` в `Epoc32/release/thumb/urel` своего SDK.

```text
STATICLIBRARY n70https.lib
LIBRARY euser.lib esock.lib insock.lib efsrv.lib estlib.lib commdb.lib hal.lib
```

STATICLIBRARY необходим, чтобы код библиотеки обрабатывался до системных
импортов и runtime GCC. Библиотека не предназначена для WINSCW.
Создавать и использовать объект нужно в одном рабочем потоке. Для Request API
стек рабочего потока — 64 КиБ; готовый пример в N70Test уже настроен.

```cpp
#include "n70https.h"
#include "testanchor.h" // пример в каталоге examples SDK ZIP

br_x509_trust_anchor anchors[TEST_ANCHOR_COUNT];
InitTestAnchors(anchors);
CN70Https* client=CN70Https::NewL();
CleanupStack::PushL(client);
client->GetAutoL(_L8("example.com"),_L8("/"),
    anchors,TEST_ANCHOR_COUNT,
    _L("C:\\system\\apps\\MyApp\\rng-device-v1.bin"),
    response,ETrue);
CleanupStack::PopAndDestroy(client);
```

Для простого экспериментального варианта достаточно GetAutoL — предварительно
инициализировать генератор приложению не нужно. Для проверенного источника
использовать GetL с собственным seed либо подготовленное индивидуальное состояние.
У GetL/GetWithStoredEntropyL последний аргумент `aHeadersOnly=ETrue` позволяет
получить только HTTP-заголовки — используется в серии тестов. По умолчанию EFalse.
`aPromptForAccessPoint=ETrue` показывает выбор точки доступа при первом запросе
объекта; последующие запросы повторно используют соединение до удаления объекта.

Проверяются цепочка сертификатов, имя DNS и сроки; передаётся SNI. Код Symbian
возвращается через Leave, подробности доступны через TlsError(), StageName(),
NetworkError(), ProtocolVersion(). Приложение нужно перекомпилировать при
обновлении библиотеки. Anchors должны оставаться в памяти до завершения запроса.

Старые GetL/GetAutoL сохраняют ограниченный буфер исходного ответа и порт 443;
они не выполняют новое HTTP-декодирование. Request API поддерживает явный порт
HTTPS, GET/HEAD/POST/PUT/PATCH/DELETE, заголовки, gzip и streaming — см. HTTP_API.md. IPv6,
Unicode URL, Brotli, HTTP-прокси и проверка отзыва сертификатов пока не добавлены.
Общий deadline и cancellation охватывают также старые методы; callback и
синхронные вычисления/файловые вызовы отменяются кооперативно после возврата.
Нельзя считать частичный ответ полным при ошибке. Прежний одиночный тест
сохраняет ограничение 64 КиБ. Новые функции выделяют память под буферы/парсер,
не под всё тело ответа. Расход памяти и скорость на N70 ещё не измерены.

## Сборка

Нужны S60 2nd FP3 SDK и ActivePerl 5.6.1 build 638, проект на том же диске,
путь без пробелов. Из PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/prepare.ps1
.\build-and-log.cmd
```

При необходимости передать prepare.ps1 параметры -Sdk и -Perl. Скрипт
скачивает/распаковывает BearSSL 0.6 в vendor/bearssl-0.6 и создаёт локальную
копию SDK в build/sdk; PATH меняется только в дочернем процессе. Старый Cygwin
падал в песочнице агента, вне песочницы сборка работает.
Сначала собирается неизменённый HelloWorldBasic из SDK, затем библиотека и тест.

Корни в library/certs/*.der проверяются по фиксированным отпечаткам; см. library/certs/README.md.
prepare.ps1 добавляет const к указателям в двух таблицах BearSSL (hashes и
HASH_OID), чтобы DLL приложения не содержала изменяемых глобальных данных.
Общий SIS не включает bootstrap.bin и не создаёт общий начальный секрет.
Скрипты из Trash/obsolete-tools/new-bootstrap.ps1 и Trash/obsolete-tools/new-test-seed.ps1 относятся к прежним версиям
и при текущей сборке не вызываются. Логи сборки не содержат секретов.

BearSSL — MIT, лицензия включена в SDK ZIP. GUI основан на Nokia
HelloWorldBasic, уведомления Nokia сохранены; права на SDK регулируются
собственной лицензией Nokia. Тесты на ПК описаны в tests/README.md.
